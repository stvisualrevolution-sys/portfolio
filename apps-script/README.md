# 問い合わせフォームの受け口（Google Apps Script）

> **設置済み。** 2026-08-02 にデプロイし、`contact.html` の `ENDPOINT` に URL を設定済み。
> 疎通確認（POST → 302 → `{"ok":true}`、CORS ヘッダあり、ハニーポット作動）まで確認済み。
> 以下は再設置するときと、設定を変えるときのための手順。

`contact.html` のフォームが送信されると、この Apps Script が受け取って

1. スプレッドシートに1行記録し（**初回に自動で作られる**。事前に用意する必要はない）
2. `stvisualrevolution@gmail.com` に通知メールを送り
3. 送信してくれた人にも自動返信を出す

という動きをする。費用はかからない。

GitHub Pages は静的ホスティングでサーバー側の処理が動かせないため、この部分だけ外に置いている。

---

## 設置手順（初回のみ・5分）

やることは **貼る → デプロイ → URLを渡す** の3つだけ。

> **先に確認**: ブラウザで **`stvisualrevolution@gmail.com` にログインした状態**で始めること。
> メールはこのスクリプトを動かすアカウントから送信されるため、
> 別のアカウントで作ると自動返信の差出人がそちらになってしまう。
> Google に複数ログインしている場合は、右上のアイコンから切り替えるか、
> シークレットウィンドウでこのアカウントだけログインして作業すると確実。

### ① スクリプトを貼る

ブラウザのアドレスバーに **`script.new`** と入力して開く。
新しい Apps Script プロジェクトがその場で作られる。

エディタに `function myFunction() {}` と書かれているので、**中を全選択（⌘A）して削除**し、
`contact.gs` の中身をまるごと貼り付ける（⌘V）。

左上の「無題のプロジェクト」を押して **`portfolio-contact`** などに改名しておくと、
あとで探しやすい。**⌘S で保存**。

### ② ウェブアプリとしてデプロイ

右上の青いボタン **デプロイ → 新しいデプロイ**

左上の歯車（種類の選択）を押して **ウェブアプリ** を選ぶ。そのあと:

| 項目 | 選ぶもの |
|---|---|
| 説明 | 空でよい |
| 次のユーザーとして実行 | **自分** |
| アクセスできるユーザー | **全員** ← ここが最重要 |

「アクセスできるユーザー」が **全員** でないと、サイトから送信できない。
実行するのは自分のアカウントなので、これで他人にスプレッドシートが見えるわけではない。
外から呼べるのは「フォームを受け取る窓口」だけ。

**デプロイ** を押すと承認を求められる:

1. 「アクセスを承認」→ 自分の Google アカウントを選ぶ
2. **「このアプリは Google で確認されていません」** という赤い警告が出る
   → **詳細** → **「（プロジェクト名）に移動（安全ではないページ）」**
   自分で書いたスクリプトなので問題ない。Google の審査を受けていない、という意味でしかない
3. 求められる権限（Gmail の送信・スプレッドシートの作成）を確認して **許可**

### ③ URL をコピーして渡す

デプロイ完了画面の **ウェブアプリ** の下に出る URL をコピーする。

```
https://script.google.com/macros/s/AKfycb................................/exec
```

この URL を `contact.html` の下のほうにあるこの行に貼れば完成:

```js
var ENDPOINT = 'PASTE_APPS_SCRIPT_WEB_APP_URL_HERE';
```

### ④ 動作確認

Apps Script のエディタに戻り、上部の関数プルダウンから **`testSend`** を選んで **実行**。

- `stvisualrevolution@gmail.com` にメールが2通（通知＋自動返信）届く
- Google ドライブに「ポートフォリオ 問い合わせ」というスプレッドシートができ、1行入っている

両方そろえば設定完了。そのあと公開ページから実際に1件送って確認する。

## あとから設定を変えるとき

`contact.gs` の上のほうにある設定値を書き換える。

| 変数 | 意味 |
|---|---|
| `TO_EMAIL` | 通知の宛先。変えればそのまま届き先が変わる |
| `AUTO_REPLY` | `false` にすると送信者への自動返信を止める |
| `MAX_PER_HOUR` | 1時間あたりの受付上限。連投・いたずら対策（既定 20件） |
| `SS_NAME` | 自動作成されるスプレッドシートの名前 |

### 変更を反映させる方法（ここだけ注意）

コードを直したあと「**新しいデプロイ**」を作ると **URL が変わってしまい、サイト側が繋がらなくなる**。

必ずこの順で更新する:

> **デプロイ → デプロイを管理 → 鉛筆アイコン → バージョン「新バージョン」→ デプロイ**

これなら URL は変わらないので、`contact.html` を触らなくていい。

## 保存先のスプレッドシート

初回の実行時に自動で作られ、その ID をスクリプトのプロパティに覚えている。
2回目以降は同じシートに追記される。

もし間違って消してしまっても、次の送信時に新しく作り直されるので壊れない
（消したぶんの記録は戻らないが、メールは残っている）。

---

## 送信の仕組み（触る必要はないが念のため）

Apps Script のウェブアプリは POST に対して別ドメインへリダイレクトを返すため、
ブラウザによっては CORS で応答が読めない。そのため `contact.html` 側は三段構えにしてある:

1. まず `Content-Type: text/plain` の単純リクエストで投げる（プリフライトが起きない）
2. CORS で弾かれたら `mode: 'no-cors'` で投げ直す（応答は読めないが送信は届く）
3. どちらも失敗したら、画面にメールアドレスを出して直接連絡してもらう

3の宛先は JavaScript の中で文字列を組み立てているので、
HTML をそのまま読むだけの収集ボットには拾われない。

## 上限のめやす

- 無料の Gmail アカウントでは、Apps Script からのメール送信は **1日100通** まで。
  1件の相談で通知＋自動返信の2通を使うので実質1日50件。まず届かない上限。
- 送信枠が尽きかけたときは自動返信を止めて、自分あての通知を優先するようにしてある。

## 迷惑メール対策

- **ハニーポット**: 人間には見えない入力欄があり、埋まっていた送信は破棄する
- **受付上限**: 1時間に `MAX_PER_HOUR` 件を超えた分は受け付けない
- **サーバー側の再検証**: 必須項目とメール形式を、ブラウザ側だけでなくここでも見ている

これで足りなくなったら Cloudflare Turnstile（無料の CAPTCHA）を足す。
